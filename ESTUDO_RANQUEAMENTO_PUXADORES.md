## 7. Diretrizes Definidas para a Checklist Dinâmica (Alinhamento Everton)

Com base nos dados dos últimos 3 meses e nas definições passadas pelo Everton para o fluxo do vendedor/projetista:

### 7.1 Comportamento do Campo (Combobox Editável com Autocomplete)

Em vez de uma lista fechada (`<select>`) com opção `"Outro"` separada, os campos de **Modelo** e **Cor** devem funcionar como **campo de texto editável com lista de sugestões**:

- **Estado inicial:** começa **em branco**.
- **Seleção como atalho:** ao clicar/selecionar um item da lista, o texto daquele item é inserido no campo apenas para facilitar o preenchimento — **o texto continua totalmente editável**.
- **Digitação livre + autocomplete:** o vendedor pode ignorar a lista e digitar diretamente qualquer modelo ou cor; conforme digita as primeiras letras, a lista já filtra/sugere os itens correspondentes.
- **Sem item `"Outro"`:** não é necessário existir `"Outro"` nem campo extra condicional, pois o próprio campo aceita edição e texto livre.

> **Nota técnica:** um combobox simples feito direto em React (sem biblioteca externa) é preferível ao `<datalist>` nativo do HTML porque mantém o mesmo comportamento e visual tanto no computador quanto no celular.

### 7.2 Ativação, Obrigatoriedade e Autopreenchimento de Cor

- **Pergunta gatilho:** *"Tem puxador?"* (`Sim` / `Não`).
  - Se **`Não`**: não exige modelo nem cor (cobre os casos de `"Sem Puxador"`).
  - Se **`Sim`**: **tanto o Modelo quanto a Cor passam a ser obrigatórios** para avançar/concluir.
- **Autopreenchimento para modelos de cor única (`Madri` e `Florença`):**
  - Confirmado pelo Everton que **Madri** e **Florença** possuem **apenas uma cor**.
  - Assim que o usuário seleciona (ou confirma com Enter) `Madri` ou `Florença`, o campo **Cor** ao lado é preenchido **automaticamente** com `"Não se aplica"` (ou `"Sem cor"`), cumprindo a obrigatoriedade sem que o vendedor precise digitar nada.
  - Se o usuário trocar o modelo depois (por exemplo, de `Madri` para `Roma`), o campo **Cor** limpa o `"Não se aplica"` e volta a exigir/sugerir as cores do novo modelo.

### 7.4 Pontos Restantes para Fechar no PRD

1. **Escopo de portas de alumínio/vidro:** decidir se o preenchimento cobre apenas puxadores de móveis ou se também terá campo separado para portas `Allure`/`Villaggio` (`Fosco`, `Bronze`, `Preto`).
2. **Tamanho do Madri:** confirmar se a sugestão será apenas `"Madri"` ou se precisa distinguir `"Madri 150mm"` / `"Madri 270mm"`.
3. **Texto padrão e edição em cor única:** confirmar o texto exato do autopreenchimento (`"Não se aplica"` vs `"Sem cor"`) e se o campo de cor fica travado ou apenas pré-preenchido quando o modelo for `Madri`/`Florença`.
